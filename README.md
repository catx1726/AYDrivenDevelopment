# AYDrivenDevelopment

给 AI 编码装上纪律的工程化 SOP 模板。AI 写代码快，但会**失控**（危险操作、自作主张）、**失忆**（上下文腐烂）、**重复踩坑**。这个模板把工程纪律变成环境规则，让 AI 干活又快又稳，经验还能攒下来。

## 有什么用

| | 一句话 | 具体怎么做 |
|---|--------|-----------|
| **复利**<br>经验滚雪球 | 每次任务都留下资产，AI 不重复踩坑 | 决策产生时即时归档；踩过的坑变成检查规则；棘手问题沉淀为 playbook——下次任务直接站在这些积累之上 |
| **控制**<br>AI 不越权 | AI 只在你拍板的地方行动 | 需求确认、计划批准、合并把关三个暂停点等你指令；危险命令提交前被钩子拦截；AI 说"做完了"必须附测试证据 |
| **提效**<br>快而不乱 | 小任务不走过场，长任务不失忆 | 小修复走 3 步轻量通道；长任务上下文超 128k 自动预警并交接，防止 AI 发散遗忘 |

> **为什么全程用 GitHub Issue/PR**：任务在线可追溯（换电脑、换会话不丢进度）、CI 自动把关（提交即检查）、PR 是质量关口——进度和资产存在云端，不依赖某次 AI 会话。

## 该怎么用

**一次性接入**（二选一，10 分钟）：

- **母库引用（推荐）**：clone 本库 → 按 `docs/superpowers/child-repo-guide.md` 接入你的项目
- **全量复制**：模板文件复制进项目根目录 → 运行 `./scripts/setup-dev.sh`（Windows: `.ps1`）

**日常使用**：在你的项目里对 AI 说——

> "在开始编码之前，请先阅读我们的规范、流程 AI SOP 仓库（母库路径）"

AI 会先跑接入自检（`check-adoption`，缺什么会告诉你装什么），然后按生命周期执行：需求澄清 → Spec（你确认）→ Plan（你批准）→ TDD 执行 → 验证 → PR（你把关）。

**用完之后**：有摩擦就给母库提 issue（lifecycle 末尾 AI 会主动汇总草稿）——你获得工程复利，模板也随反馈进化。
